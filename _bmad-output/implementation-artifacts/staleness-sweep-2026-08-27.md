## 4. Drift pattern and one process fix

**What actually goes stale: discrete, mergeable CI/infra/asset deliverables — and nothing else.** All three flips (AI-23, AI-49, AI-52) shipped inside a PR aimed at something else, two of them *self-cite their own item id in-source or in the commit body*, and the only failure was the status field. Zero product/policy items resolved.

**What never resolves: human-owned decisions and written-policy items** (AI-20, AI-54, AI-55, AI-57, AI-58, AI-64, AI-65, AI-68). These don't go stale — they go round. AI-21 → AI-40 → AI-57 is the same ask under three ids; AI-18/19/21 were bundled into AI-40, which is itself open; AI-33's residual and AI-39 are the same work at two severities; AI-59 is subsumed by AI-63(b), which is open. The ledger accretes duplicates instead of closing.

**Third pattern — the lesson gets applied to the sibling, not to the target.** AI-3's restore-keys lesson went into the tarpaulin and nextest caches but never into the semver job it names (and both copies reproduce the AI-3 defect); AI-26's `allow_hyphen_values` fixed `agent send` but not `config set`; AI-16's `list_spawn_records` batch API was built for `adopt_orphans` and never wired into `fleet()`; AI-24/AI-28's atomic-write helper still doesn't exist. Local patch lands, class stays open, item looks addressed.

**Fourth — the tracker over-credits itself.** 8 of the 11 adversarially verified claims were refuted, *all in the same direction*: crediting work nobody did. Three entries assert things false against the tree (AI-32's PR #48 claim, AI-56's quoted dead key, AI-70's uncited "AI-49 remains open"). Location drift (AI-13, AI-15, AI-24, AI-34, AI-41) forces every sweep to re-derive the same facts.

**Concrete fix — an `AI-N` consistency gate in the existing python gate scripts** (`scripts/check_docs.py` / `test_automation.py`, already wired at `ci.yml:207`): fail a PR when the diff or commit message mentions `AI-<n>` while `sprint-status.yaml` still lists that item `open`, unless the PR body carries an explicit `Refs AI-<n> (not closing: <reason>)` line. Every one of this sweep's three flips would have been caught at merge time — `ci.yml` says "AI-23", `crash.rs:149` says "AI-49", `884b974`'s body says the AI-52 brief is fulfilled. Cheap rider in the same script: enforce the already-ratified §6 rule (`sprint-change-proposal-2026-08-26.md`) that a status flip requires a commit/PR citation, and add an `owner: human` flag so decision items are reported in their own list and stop being re-swept as code staleness.
