## Findings

### A. The headline gap (verification lens)

- **A1 [fix-now, high] — the frozen v1 Rust surface has no active guard.** The AC's named enforcement is the semver-check CI job, but it is dormant until 7-4 publishes a crates.io baseline (`ci.yml` 404 branch emits a notice and exits green; the dormancy is disclosed in `crates/ktesio-adapter-api/src/lib.rs:44-45` and `docs/adapter-contract.md`). No other verification fails on a public-surface break: a commit that removes/renames a public `ktesio-adapter-api` item and fixes up in-workspace call sites passes every gate. Suggested shape: a public-API inventory pin test (sorted `pub` item paths + signatures, the repo's frozen-list style) until cargo-semver-checks arms at 7-4.

### B. Cross-story seams (edge-case + adversarial lenses)

- **B1 [fix-now, high] — the legacy start fallback re-reads `adapter.toml` without renegotiating.** `crates/ktesio-engine/src/adapter/mod.rs:290-303`: the launch-less/legacy snapshot fallback re-parses the manifest at start time, so a manifest edited to a 2.x `contract_version` after registration starts via the fallback, bypassing the 6-6 load gate. Fix: call `negotiate_contract_version` on the fallback path + a test.
- **B2 [fix-now, med] — frozen contract text contradicts the code on stdin piping.** `docs/adapter-contract.md:25-50` says the engine pipes the child's stdin "whenever interaction is not declared unsupported"; the supervisor pipes only for Guaranteed|BestEffort (`supervisor.rs:582`). Unsupported-interaction adapters spawn with no stdin pipe. Frozen text must be corrected to match shipped behavior.
- **B3 [fix-now, med] — negotiation's manifest-only scope is undocumented.** `negotiate_contract_version` runs on the manifest load path only; native builtins (hermes, mock) declare no contract version and can never fail it, while `docs/adapter-contract.md` opens with "applies uniformly to both adapter kinds."
- **B4 [fix-now, low] — exit-code docs omit the contract-incompatible cause.** `AgentContractIncompatible` maps to exit 1, but `docs/commands.md`'s public exit-code table names only "invalid or unreadable adapter manifest."
- **B5 [fix-now, low] — `declared` field dual definition.** `docs/commands.md` defines memory-attach `--json` `declared` both as "the adapter's declared config mapping targets memory.dir" AND "always false for native" — these disagree for hermes (a native adapter WITH a declared `memory.dir` → `HERMES_HOME` mapping); the same passage misstates hermes as owning memory entirely.
- **B6 [defer] — TCK is channel-blind.** `run_interaction` (tck.rs) never reads the declared `[interaction].channel`; an HTTP-channel adapter (legalized by CP-6.5-a) gets `interaction: pass` via the stdin echo probe. Neither adapter-contract.md nor testing.md tells adapter authors the section is channel-blind. Docs note now; channel-aware TCK section needs engine work → post-v1.
- **B7 [defer] — ratified v1 duties the TCK cannot prove** (`{env:VAR}` render guarantee, self-update pinning, config-layer disclosure): no section exercises them; the contract page's "proves an adapter honors every applicable section" overstates. Distinguish declaration-checkable from honor-system duties in docs.
- **B8 [defer] — `ConformanceReport` records no contract version.** A report from a 6-6-gated engine can't say which contract major produced a pass; a wrong-major manifest surfaces as a generic all-fail "registration failed". Additive field candidate for the next conformance story (bump policy documented at tck.rs:135-137).
- **B9 [defer] — frozen trait defaults carry seed placeholder text.** `AgentAdapter`'s default bodies return "lifecycle execution is not implemented until story 1-4" (`adapter.rs`) — a stale story reference in a frozen error surface; 6-5's mapping flagged it, 6-6 froze without noting it. Text fix + announcement in a next touching story.
- **B10 [fix-now, low] — memory attach `--json` partial-state diagnostic.** After a persisted attach, an errored status read-back yields a generic failure; only the Ok(None) arm names the partial state (`kt/src/cli/agent.rs:1813-1831`).
- **B11 [defer] — TCK robustness batch:** subject-declared `memory.dir` delivery unproven (probe's own var used — hermes' `HERMES_HOME` delivery specifically untested); `declares_memory_dir` re-read failure collapses to not_applicable; `UpstreamStub::drop` wake-up failure can block on `join()` forever (tck.rs:2239-2251).

### C. Aggregate views

- **C1 [accept] — architecture delta is declared and gated.** Two new internal edges: engine → adapters-hermes (normal; the hermes builtin lives inside the core crate — CI-gated via the AD-2 allowlist, rationale inlined at `ci.yml:264-275`) and conformance → engine (normal; the TCK is a consumer of the public engine API). No normal-dep cycles; kt's normal graph verified free of conformance. The durable hexagonal-boundary fact (a concrete adapter inside the engine crate) lives only in Cargo.toml comments — worth a sentence in architecture.md.
- **C2 [fix-now, med] — manifest-fixture duplication grew instead of consolidating.** ~16 builder functions emitting near-identical adapter-TOML across 12 engine test files + tck.rs + kt tests (~400-500 lines); the story 5-1 deferral explicitly named Epic 6 as the forcing function ("once Epic 6's conformance kit forces the shape anyway") and epic 6 instead added 4+ more copies, keeping the TCK's generalized `write_probe_manifest` private. Also: `install_shim` duplicated verbatim (`hermes.rs:377` / `hermes_tck.rs:51`), and `agent_cli.rs` uses two different fake_agent resolution mechanisms in one file (local `CARGO_BIN_EXE_kt` copy at :543 + `ktesio_conformance::fake_agent_bin()` at :1727). Consolidation action item: a shared test-support module.
- **C3 [defer] — size growth concentrated but compositional.** tck.rs 0→3701 (section-partitioned, documented; the real cohesion costs are the recorded 6-4 deferrals: storage-internals coupling, non-configurable harness); `kt/src/cli/agent.rs` 3430→3690 (the entire agent surface in one flat module — module-split candidate for an ergonomics story); `adapter/mod.rs` crossed ~1500 (resolution + config-apply/file-write co-located); supervisor.rs untouched by the epic (its 5746 lines are pre-existing).
- **C4 [accept] — pattern divergence: none found.** Error typing (thiserror per layer, per-variant remediation docs), test naming/assertion style, doc-comment discipline, and wire conventions (per-family `*_SCHEMA_VERSION` consts, snake_case) all match house style. `ConformanceReport` is a second frozen schema family created in-epic; it self-documents its bump policy.
