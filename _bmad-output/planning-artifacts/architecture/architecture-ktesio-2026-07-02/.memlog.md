- (decision) AD-1 Paradigm = Hexagonal (ports & adapters) around a supervised-process core. Engine core = pure domain (state machine, ledger, budget evaluation, config resolution); ports = AgentAdapter (down), EmbeddingInterface (up, = engine crate public API), MeteringSource, MemoryBacking, StateStore, ProcessBackend; adapters/frontends = hermes adapter, manifest-driven generic adapter, kt CLI, per-OS process backends. Prevents domain logic leaking into CLI/agent/OS-specific code — the divergence that would kill cross-agent uniformity (SM-1).
- (decision) AD-2 Cargo workspace: crates/ktesio-engine (lib; public API = Embedding Interface), crates/ktesio-adapter-api (Adapter Contract types + traits, separately semver'd so adapters don't depend on engine internals — PRD §7 independence), crates/ktesio-adapters-hermes (reference native adapter), crates/ktesio-conformance (TCK + mock adapter, FR-27), crates/kt (bin; depends ONLY on ktesio-engine public API + adapter-api types where needed). Legacy skills-manager modules live on inside kt for the deprecation window (FR-37..39) then delete. Rationale: separate adapter-api crate is the cheapest honest boundary for third-party adapter authors; conformance as crate makes SM-1 interim measurement a cargo test.
- (decision) AD-3 Two adapter kinds behind one AgentAdapter trait: NATIVE (Rust impls compiled in: hermes, mock) and MANIFEST (declarative adapter.toml in a directory: exec/args/env templates per lifecycle op, capability declaration, metering-source config, interaction wiring). FR-1 "local Adapter supplied by path" = manifest kind — no dylib loading (rejected: ABI-unsafe Rust plugins), no scripting runtime. opencode paper-check maps to the manifest kind. Prevents two incompatible extension mechanisms emerging.
- (decision) AD-4 Per-OS ProcessBackend port: Unix = spawn into own process group, graceful stop = SIGTERM → SIGKILL after configurable window; Windows = Job Object per Agent Instance, stop = CTRL_BREAK/graceful request → TerminateJobObject. Pause: Unix optionally SIGSTOP/SIGCONT ONLY when the adapter declares pause guaranteed-via-signal; Windows pause is adapter-cooperative only. Therefore Capability Declaration is keyed (capability × OS) — a single flat capability list would silently lie on Windows (FR-7/NFR-2 honesty).
- (decision) AD-5 Orphan adoption (NFR-1): write-ahead spawn record (PID + process start-time fingerprint + instance id) persisted BEFORE exec returns; on engine start, reconcile records vs live processes — matching fingerprint → adopt supervision; missing → mark failed with last-known cause. Prevents both orphan leaks and PID-reuse false adoption.
- (decision) AD-6 State store = SQLite via rusqlite (bundled sqlcipher OFF, bundled sqlite ON), single DB at engine state dir, WAL mode, synchronous=NORMAL; per-instance bulky artifacts (logs, memory dirs, skills) stay as files in the Agent Home. Usage Ledger = append-only usage_events table + rolled-up aggregates; every event insert is a txn → durability loss bound ~0 (beats PRD's ≤5s placeholder; ratify ≤1s). Rejected: JSON files (concurrent kt + embedded-host access unsafe), event-log store (overbuild for v1). New-dep sign-off: justified under NFR-8, flagged to Islam.
- (decision) AD-7 Metering/enforcement path is ONE internal pipeline: MeteringSource emits UsageEvent → ledger txn → BudgetEvaluator runs inside the same commit path → on breach emits BreachDecision → supervisor executes Breach Action (default pause per Islam) + event out. Enforcement latency = event arrival + evaluation (<1s; PRD FR-21 bound ratified). engine-observed source v1 = loopback-only HTTP forward listener the adapter points the agent's OpenAI-compatible base_url at; parses standard usage fields from responses. - (decision) AD-9 Config = TOML everywhere; layered resolution defaults < adapter-manifest kind defaults < Agent Home instance config < invocation overrides; resolution produces a persisted EffectiveConfig snapshot in the Agent Home at start, each value carrying its source layer (FR-13 provenance). - (decision) AD-10 Secrets: config references secrets by indirection (`secret:NAME`); v1 resolvers = process env + engine secrets file (0600). - (decision) AD-11 MemoryBacking port; v1 impls: `filesystem` (engine-managed dir inside Agent Home, survives restarts byte-identically) and `native` (delegation marker; engine guarantees only Agent Home persistence). - (decision) AD-12 Interaction & logs: InteractionChannel part of the adapter trait — manifest adapters default to stdin pipe (input) + stdout/stderr capture; hermes native adapter maps to its CLI/gateway channel. Engine captures agent stdout/stderr into per-instance rotated log files: 10MB × 3 rotations (PRD FR-25 10MB placeholder → ratified as 10MB×3), lines timestamped + attributed (agent-out | agent-err | engine).
- (decision) AD-13 Engine is async-first on tokio (multi-thread runtime): process supervision, loopback metering listener, timers, and event fan-out multiplex naturally; kt wraps calls via a small blocking facade (engine exposes both async API and a blocking() adapter).
