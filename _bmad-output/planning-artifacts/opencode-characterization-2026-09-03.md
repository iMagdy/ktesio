## 1. Identity

**CONFIRMED.** opencode is an open-source AI coding agent: "OpenCode is an open source AI coding agent. It's available as a terminal-based interface, desktop app, or IDE extension" (<https://opencode.ai/docs/>, accessed 2026-09-03). One TypeScript/Bun codebase, distributed as one `opencode` binary; the docs index and CLI reference describe a single command surface (TUI subcommand default, plus `serve`/`attach`/`run`/`acp`/`stats`/`upgrade`/… — 24 top-level command modules plus the `debug/` subcommand tree in `packages/opencode/src/cli/cmd/` at the pin). It is model-agnostic: "OpenCode uses the AI SDK and Models.dev to support 75+ LLM providers and it supports running local models" (<https://opencode.ai/docs/providers/>, accessed 2026-09-03). Structurally UNLIKE Hermes on every axis FR-29 names: session model (server-side, many sessions per process), process shape (spawned foreground server, no service installer, no gateway verbs), metering surface (message-attached accounting, no usage slash-command, no analytics DB).

## 2. Process / lifecycle model

**CONFIRMED — client/server by construction, spawned foreground, no daemon.**

| Claim | Verdict | Evidence |
|---|---|---|
| TUI + server from one process tree | CONFIRMED | "When you run opencode it starts a TUI and a server" — the TUI is a client of that server (<https://opencode.ai/docs/server/>, accessed 2026-09-03). |
| `opencode serve` = headless HTTP server | CONFIRMED | `ServeCommand` — "starts a headless opencode server"; the handler ends in `yield* Effect.never` (runs forever in the foreground; there is no daemonize/detach flag anywhere in the option set) — `packages/opencode/src/cli/cmd/serve.ts:6-24` @ `4b7e19e`; flags limited to `--port/--hostname/--mdns/--mdns-domain/--cors` (`packages/opencode/src/cli/network.ts:5-31`); the CLI docs list no `--daemon`/`-d` (<https://opencode.ai/docs/cli/>, accessed 2026-09-03). |
| Default bind 127.0.0.1, port **prefers** 4096 with silent fallback | CONFIRMED, with a supervision caveat | hostname default `"127.0.0.1"` and port default `0`, where port `0` "prefers 4096 first, then any free port" — **silently** (`packages/opencode/src/cli/network.ts:9-16`, `packages/opencode/src/server/server.ts:117-122` @ `4b7e19e`); the server docs table states port default `4096`, hostname `127.0.0.1` (<https://opencode.ai/docs/server/>, accessed 2026-09-03). A supervisor therefore cannot assume 4096: when 4096 is taken, the endpoint moves without an error — the chosen port must be learned from the server's own startup line ("opencode server listening on http://<host>:<port>", `serve.ts:20`) or pinned explicitly via `--port`. Feeds mapping freeze-risk R8. |
| `opencode attach` joins a running backend | CONFIRMED | `attach <url>` — "attach to a running opencode server" (`packages/opencode/src/cli/cmd/attach.ts:7-16`); docs: "Attach a terminal to an already running OpenCode backend server started via serve or web commands" (<https://opencode.ai/docs/cli/>, accessed 2026-09-03). |
| One process hosts MANY sessions | CONFIRMED | Sessions are server-side objects with a full CRUD surface — `GET/POST /session`, `GET/DELETE/PATCH /session/:id` (`packages/opencode/src/server/routes/instance/httpapi/groups/session.ts:78-107` @ `4b7e19e`; <https://opencode.ai/docs/server/>, accessed 2026-09-03). Nothing binds a session to a process lifetime. |
| HTTP basic auth available | CONFIRMED | `OPENCODE_SERVER_PASSWORD` (username defaults `opencode`, overridable via `OPENCODE_SERVER_USERNAME`); `serve` warns when unset — `packages/opencode/src/cli/cmd/serve.ts:15-17` @ `4b7e19e`; <https://opencode.ai/docs/server/> and `/docs/cli/` (accessed 2026-09-03). |
| Exit codes / signal handling | OPEN | Not documented anywhere on the CLI reference (<https://opencode.ai/docs/cli/>, accessed 2026-09-03); no signal-contract code path surfaced in the CLI/server modules at the pin. No graceful-stop verb exists (see §3); stop = whatever the supervisor's signal semantics are. |

**Readiness (relevant to Ktesio's crash detection):** `GET /global/health` — "Get health information about the OpenCode server" — returns `{ healthy: true, version }` (`packages/opencode/src/server/routes/instance/httpapi/groups/global.ts:69`, handler at `.../handlers/global.ts:66-68` @ `4b7e19e`; documented at <https://opencode.ai/docs/server/>, accessed 2026-09-03). Secondary readiness/liveness proxies: the OpenAPI 3.1 spec at `GET /doc` (`packages/opencode/src/server/server.ts:67-69`) and the SSE stream whose **first event is `server.connected`** (`.../handlers/global.ts:41` for `/global/event`, `.../handlers/event.ts:70` for the per-instance `/event` stream; docs: "First event is server.connected, then bus events"). A `server.heartbeat` SSE tick every 10 s exists on `/global/event` (`.../handlers/global.ts:35-38`).

## 3. Lifecycle verbs

**CONFIRMED — there are none, and that is the finding.** The CLI command surface at the pin is 24 top-level modules (`account, acp, agent, attach, cmd, db, export, generate, github, import, mcp, models, plug, pr, prompt-display, providers, run, serve, session, stats, tui, uninstall, upgrade, web`) plus the `debug/` subcommand tree (`packages/opencode/src/cli/cmd/` @ `4b7e19e`) — **no `start`/`stop`/`restart`/`status` service verbs** (contrast Hermes' gateway verb set). The one `uninstall` command removes the opencode **binary installation** itself; it is not an OS-service verb and has no Hermes-style install/uninstall-of-launchd/systemd-units counterpart. A repo-wide grep for `SIGSTOP`/`SIGCONT` at the pin returns **zero hits**. `POST /session/:id/abort` — "Abort an active session and stop any ongoing AI processing or command execution" (`packages/opencode/src/server/routes/instance/httpapi/groups/session.ts:253-263`, identifier `session.abort`, description at `:262` @ `4b7e19e`; <https://opencode.ai/docs/server/>, accessed 2026-09-03) — ends one session's in-flight work while the server process keeps running and hosting every other session: **abort ≠ process stop**. `POST /session/:id/revert`/`unrevert` undo file/session state, not process state (`groups/session.ts:369-383`).

**Pause: no surface of any kind.** No pause/suspend endpoint exists in any HTTP route group (`SessionPaths` and the global/instance groups at `packages/opencode/src/server/routes/instance/httpapi/groups/` @ `4b7e19e`), no pause CLI command exists, and the only `suspend` match in the CLI/server tree is `terminalSuspend` in `packages/opencode/src/cli/cmd/run/runtime.boot.ts:71` — TUI terminal scrollback control on non-Windows, not agent-execution suspension. For the Adapter Contract this makes opencode the real-world bearer of the `pause: unsupported` declaration the mock only synthesizes.

## 4. Config mechanism

**CONFIRMED — layered JSON, env injection, variable substitution; supervisor-friendly.**

- **Files & scopes:** global `~/.config/opencode/opencode.json`; project `opencode.json` at the project root; `.opencode/` directories also carry config/agents/commands/plugins; TUI settings in `tui.json` (<https://opencode.ai/docs/config/>, accessed 2026-09-03). Managed (enterprise) dirs: `/Library/Application Support/opencode/` (macOS), `/etc/opencode/` (Linux), `%ProgramData%\opencode` (Windows), plus macOS MDM preferences (<https://opencode.ai/docs/config/>, accessed 2026-09-03).
- **Merge order (later overrides earlier), docs:** remote `.well-known/opencode` → global → `OPENCODE_CONFIG` file → project → `.opencode` dirs / `OPENCODE_CONFIG_DIR` → inline `OPENCODE_CONFIG_CONTENT` → managed files → MDM (<https://opencode.ai/docs/config/>, accessed 2026-09-03). Source agreement at the pin, including the tail the fact sheet missed: global dir merge, then `Flag.OPENCODE_CONFIG`, then project files (`packages/opencode/src/config/config.ts:407-424`), `.opencode`/`OPENCODE_CONFIG_DIR` files, then `OPENCODE_CONFIG_CONTENT` (`config.ts:482-490`) — **`OPENCODE_CONFIG_CONTENT` is NOT merged last.** After it, the chain merges active-org/account remote config (`config.ts:492-527`), the enterprise **managed dir's** `opencode.json`/`opencode.jsonc` (`config.ts:530-536`), and macOS **MDM managed preferences, which the source comments "override everything"** (`config.ts:538-547`); a late `OPENCODE_PERMISSION` env override follows, permissions only (`config.ts:559-564`). "Configuration files are merged together, not replaced" (docs). **Supervision implication:** config delivered via `OPENCODE_CONFIG_CONTENT` can be overridden on that machine by an enterprise-managed file or MDM profile — the "supervisor-provided config is authoritative" story holds only on machines without managed config (flagged in the mapping's CP-6.5-e and freeze-risk R5).
- **Env injection:** `OPENCODE_CONFIG` (a file path) and `OPENCODE_CONFIG_CONTENT` (inline JSON) are captured from the environment (`packages/core/src/flag/flag.ts:21-22` @ `4b7e19e`). `OPENCODE_CONFIG_CONTENT` means the **entire runtime config can be delivered as an env-var value** — no file write needed. This is the single most adapter-relevant config fact: a supervisor can hand opencode its configuration without touching its config schema's file layout.
- **Substitution:** `{env:VAR}` substitutes environment variables (unset → empty string per docs); `{file:path}` also supported (<https://opencode.ai/docs/config/>, accessed 2026-09-03; implementation `packages/opencode/src/config/variable.ts:33-36` @ `4b7e19e`).
- **Published schema:** the runtime config schema is published at <https://opencode.ai/config.json> — opencode itself stamps `$schema: "https://opencode.ai/config.json"` (`packages/opencode/src/config/config.ts:397` @ `4b7e19e`; docs: "The server/runtime config schema is defined in opencode.ai/config.json"). TUI config schema at `opencode.ai/tui.json`.
- **Self-update lever:** `autoupdate: Boolean | "notify"` (`packages/core/src/v1/config/config.ts:64-68` @ `4b7e19e`). Default is ON: the startup check returns early only when `config.autoupdate === false` or `OPENCODE_DISABLE_AUTOUPDATE` is set (`packages/opencode/src/cli/upgrade.ts:9-14`); docs: "OpenCode will automatically download any new updates when it starts up" (<https://opencode.ai/docs/config/>, accessed 2026-09-03). **A Ktesio supervisor must pin `autoupdate = false` (or export `OPENCODE_DISABLE_AUTOUPDATE`) or the binary mutates itself under a running instance.**
- **Home isolation:** see §7 — `XDG_*` resolution is the lever (`OPENCODE_TEST_HOME` exists but is test-only, `packages/core/src/global.ts:20-23` @ `4b7e19e`).

## 5. Usage / metering surface

**CONFIRMED, with one correction — accounting is message-attached and derived from models.dev rates.**

- **Per-message tokens + cost:** the assistant message schema carries optional `cost: Finite` and `tokens: {input, output, reasoning, cache: {read, write}}` (`packages/schema/src/session-message.ts:165-189`, identifier `Session.Message.Assistant`, @ `4b7e19e`).
- **Session-level aggregates:** the Session object itself carries optional `cost` and `tokens` fields (`packages/opencode/src/session/session.ts:226-247` @ `4b7e19e`). **This corrects the 6-5 fact sheet** (see §9): the Session row is a denormalized aggregate, not cost-free.
- **Cost rates come from models.dev:** "OpenCode uses the AI SDK and Models.dev to support 75+ LLM providers" (<https://opencode.ai/docs/providers/>, accessed 2026-09-03); the client fetches models.dev metadata (`packages/core/src/models-dev.ts:250`) and prices each message from `model.cost` tiers, reasoning tokens billed at the output rate (`packages/opencode/src/session/session.ts:363-400` @ `4b7e19e`).
- **Batch surfaces:** `opencode stats` — "show token usage and cost statistics" — aggregates totalCost, totalTokens (input/output/reasoning/cache), per-model usage, cost/day from the session store (`packages/opencode/src/cli/cmd/stats.ts:49-81,10-47` @ `4b7e19e`; <https://opencode.ai/docs/cli/>, accessed 2026-09-03). `opencode session list --format json` exists but its JSON projection is id/title/created/updated/projectId/directory only — **no cost fields** (`packages/opencode/src/cli/cmd/session.ts:80-85,137-147` @ `4b7e19e`); the server API's `GET /session` returns the full `Session.Info` (cost included). Live streaming: the SSE/bus event `message.updated` (`packages/schema/src/v1/session.ts:596-597` @ `4b7e19e`) is what `opencode run --format json` itself consumes (`packages/opencode/src/cli/cmd/run.ts:708`).
- **Honesty labeling — a real gap:** there is **no $-denominated cap or budget anywhere** (like Hermes), and unlike Hermes' `CostStatus ∈ {actual, estimated, unknown}` labels, opencode's cost math silently coerces missing/invalid numbers to zero (`const finite = (v) => (Number.isFinite(v) ? v : 0)`, `const safe = (v) => Math.max(0, finite(v))` — `packages/opencode/src/session/session.ts:339-340` @ `4b7e19e`). A provider that omits usage renders as **silent zeros, not "unknown"** (§10, axis 7).

## 6. Interaction channels

**CONFIRMED — HTTP-native sessions are the primary programmatic channel; stdio exists only as ACP or plain process stdio.**

- **One-shot CLI:** `opencode run [message..]` — "Run opencode in non-interactive mode by passing a prompt directly", with `--format` "default (formatted) or json (raw JSON events)", `--model provider/model`, `--agent`, `--continue/--session/--fork`, and `--attach` to reuse a running server (<https://opencode.ai/docs/cli/>, accessed 2026-09-03; flags at `packages/opencode/src/cli/cmd/run.ts:127-247` @ `4b7e19e`).
- **HTTP session API:** `POST /session/:id/message` (synchronous prompt), `POST /session/:id/prompt_async` (returns 204), plus `command`/`shell` endpoints (`groups/session.ts:92-101`; <https://opencode.ai/docs/server/>, accessed 2026-09-03). The server can be driven entirely headlessly — the SDK and IDE plugins do exactly that.
- **TUI control via server:** `/tui/*` endpoints (`append-prompt`, `submit-prompt`, `open-sessions`, `execute-command`, …) drive the TUI remotely — "this is how the IDE plugins work" (<https://opencode.ai/docs/server/>, accessed 2026-09-03).
- **ACP = stdio JSON-RPC subprocess:** "To use OpenCode via ACP, configure your editor to run the `opencode acp` command. The command starts OpenCode as an ACP-compatible subprocess that communicates with your editor over JSON-RPC via stdio" (<https://opencode.ai/docs/acp/>, accessed 2026-09-03). Source: `AgentSideConnection` + `ndJsonStream` wired to `process.stdin`/`process.stdout` (`packages/opencode/src/cli/cmd/acp.ts:33-58` @ `4b7e19e`). **Structural nuance:** the ACP process *also* starts an internal HTTP server and proxies to it through the SDK (`acp.ts:19-24`) — stdio is the outer envelope, HTTP is still the spine. Editors own the ACP subprocess lifecycle; it is not a ktesio-style long-lived agent process.
- **SDK is JS/TS only:** "The opencode JS/TS SDK provides a type-safe client for interacting with the server"; "All types are generated from the server's OpenAPI specification" (<https://opencode.ai/docs/sdk/>, accessed 2026-09-03). A ktesio adapter would speak raw HTTP, not use the SDK.
- **stdin of a spawned `opencode serve` is idle** (the handler runs `Effect.never` and never reads stdin — `serve.ts:13-23`): the contract's Stdio interaction channel has no native consumer in server mode.

## 7. Memory / persistence

**CONFIRMED, with one precision upgrade over the fact sheet — the isolation lever exists in source but is undocumented.**

- **Data location:** `~/.local/share/opencode/` by default — docs confirm for WSL too: "Your OpenCode config and sessions are stored within the WSL environment at ~/.local/share/opencode/" (<https://opencode.ai/docs/windows-wsl/>, accessed 2026-09-03). Source truth: paths resolve through the `xdg-basedir` package — `data = ${XDG_DATA_HOME:-~/.local/share}/opencode`, and likewise `cache`/`config`/`state` (`packages/core/src/global.ts:2-11` @ `4b7e19e`). **So `XDG_DATA_HOME` (and `XDG_CONFIG_HOME`) ARE honored by construction** — the docs never document them (not on the config page, <https://opencode.ai/docs/config/>, accessed 2026-09-03), but the lever a supervisor needs to point an instance's data at a custom Agent Home root exists and is a plain env var. Sessions/state live in a SQLite database at `${data}/opencode.db` (`packages/core/src/database/database.ts:53` @ `4b7e19e`), with legacy per-project JSON files migrated on load (`packages/opencode/src/storage/storage.ts:83-92`); sessions are partitioned by `projectID` in the data model.
- **Sessions resumable:** `--continue` (last session), `--session <id>`, `--fork` on both `run` and `attach` (`packages/opencode/src/cli/cmd/run.ts:147-160`, `attach.ts:21-34` @ `4b7e19e`).
- **Rules/instructions (the "memory" opencode actually has):** AGENTS.md chain with Claude Code fallbacks — global `~/.config/opencode/AGENTS.md` (fallback `~/.claude/CLAUDE.md`), project AGENTS.md (fallback CLAUDE.md), "The first matching file wins in each category"; plus an `instructions` config key taking glob patterns (and remote URLs), "All instruction files are combined with your AGENTS.md files" (<https://opencode.ai/docs/rules/>, accessed 2026-09-03). Source: `packages/opencode/src/session/instruction.ts:61-66,122` and `packages/core/src/v1/config/config.ts:124` @ `4b7e19e`. `POST /session/:id/init` — "Analyze app and create AGENTS.md" (<https://opencode.ai/docs/server/>, accessed 2026-09-03).
- **No native memory store:** unlike Hermes' bounded MEMORY.md/USER.md memory system, opencode has no memory-directory concept at all — the closest behaviors are rules injection (above) and session resume. **A Ktesio filesystem Memory Backing has no native consumer to point `memory.dir` at**; this is a mapping-level finding, not a config gap.

## 8. Providers / auth

**CONFIRMED.** 75+ providers via the Vercel AI SDK + models.dev (<https://opencode.ai/docs/providers/>, accessed 2026-09-03). API keys added via `/connect` (or `opencode auth login`) are stored in `~/.local/share/opencode/auth.json` (docs; source `packages/opencode/src/auth/index.ts:10` @ `4b7e19e` — i.e. `${XDG_DATA_HOME:-~/.local/share}/opencode/auth.json`, so the same XDG lever moves the credential file). Some providers are env-var-auth only (e.g. Bedrock — docs). **Custom/loopback providers:** define a provider in `opencode.json` with `npm: "@ai-sdk/openai-compatible"` and `options.baseURL` pointing at any OpenAI-compatible endpoint (docs; source: `options.endpoint ?? options.baseURL` flows into `providerOptions.baseURL` — `packages/opencode/src/provider/provider.ts:362-365` @ `4b7e19e`). **This is the engine-observed metering hook**: a supervisor can point a provider at its own loopback listener and observe every completion call.

## 10. OPEN axes (explicit)

Each of these remains undetermined at the pin, with the evidence state named. All seven are carried into the companion mapping's freeze-risk list: **axis 1 → R4, axis 2 → R6, axis 3 → R7, axis 4 → R8 (with the port-discovery fold), axis 5 → R9, axis 6 → R10, axis 7 → R11.**

**Axis naming (epics Story 6.5 AC element):** which structural-distance axes opencode covers vs Hermes, and which the mock must cover, is named per-axis in the companion mapping's §4 axis-coverage matrix (`opencode-conformance-mapping-2026-09-03.md`) — that matrix is the discharge of the AC's "naming which structural-distance axes it covers vs Hermes and which the mock must cover" clause for this note.

1. **Exit codes / signal handling** — undocumented; no graceful-stop verb exists; stop semantics are whatever the supervisor's signals do (§2/§3; <https://opencode.ai/docs/cli/>).
2. **Undocumented-lever churn risk for `XDG_*`** — the lever works today but is not a documented interface; a release could change path resolution without a docs-visible deprecation (§7).
3. **Provider-omits-usage behavior** — source shows silent zero-coercion (no "unknown" label), but no docs statement exists; treated as an honesty-labeling gap rather than a guaranteed behavior (§5; `session.ts:339-340,363-400`).
4. **`/global/health` depth** — the endpoint returns a constant `healthy: true` plus version; it proves process liveness, not per-instance readiness (e.g. provider auth validity). Whether it suffices as a readiness probe is a Ktesio-side decision, not an opencode fact.
5. **Concurrent-instance safety on shared data dirs** — sessions/state are per-XDG-root SQLite; docs are silent on two servers sharing one data dir. A global file-lock primitive is initialized over the state root — the code expression `Flock.setGlobal({ state })` at `packages/core/src/global.ts:33` @ `4b7e19e` (path resolution at `global.ts:10-14`) — but its concurrency guarantees are undocumented → per-instance XDG roots remain the safe recommendation (→ mapping freeze-risk R9).
6. **`abort` completion semantics** — abort marks a session aborted (client observes via status/SSE), but the docs do not specify in-flight tool-process teardown guarantees.
7. **Windows-native (non-WSL) behavior** — docs recommend WSL "for the best experience" and warn terminal support is the differentiator; no supported-behavior matrix for native Windows exists (<https://opencode.ai/docs/windows-wsl/>, accessed 2026-09-03). A Ktesio Windows declaration for opencode would be best-effort at best.

## 11. Residual risks

- **Churn:** the pin moves multiple times per week (§ header). Line numbers and even endpoints (`/global/health` landed recently enough to be missing from same-day fact-sheet research) can change between story start and 6-6 freeze — the freeze decision must cite this note's SHA, and 6-6 should re-diff against any tag newer than `v1.18.27` before publishing contract v1.
- **Docs-vs-code drift:** where docs and the pinned source disagreed or diverged in detail (health endpoint; session cost fields; XDG), this note treats **the pinned source as truth** and docs as secondary.
